# ADR-001: Standalone companion extension and durable discovery

**Status:** Accepted; implementation decision retained through Milestone 2
**Target:** FreshRSS 1.30.4, release commit `08f97bd497ace733c151ea1c709d85cd5b65cc53` in the checked-in `.upstream/FreshRSS` checkout.

## Decision

Implement `xExtension-ArticleTopics` as a standalone companion extension. Reuse design techniques from `xExtension-LlmClassification`, but do not fork it or copy its code. The checked-in extension collection is at `012ac097d715ff43ba53f8fc8bd3ec7f35fc6d7`; the extension's `metadata.json` does not declare a license, and its checked-in directory contains no LICENSE or copyright notice. Its README and source alone do not establish a reuse license. Keeping this implementation independently authored avoids importing code without permission and avoids coupling topic labels to its insertion-time article-tag behavior. This repository's LICENSE identifies our project as GPL-3.0-or-later.

The upstream extension registers `EntryBeforeInsert` in `extension.php`. FreshRSS 1.30.4 documents this as a pre-insert hook (`lib/Minz/HookType.php`); `EntryDAO::commitNewEntries()` in `app/Models/EntryDAO.php` assigns committed IDs while moving `_entrytmp` rows. This is unsuitable for the required worker-owned user-label associations, which need stable entry IDs.

## Discovery and commit ordering

Do not rely on a numeric high-water cursor alone. In FreshRSS 1.30.4, `EntryDAO::commitNewEntries()` assigns IDs using `MAX(id) - COUNT(*)`, then orders temporary rows by date and temporary ID (`app/Models/EntryDAO.php`, `commitNewEntries`). Concurrent or overlapping refreshes can therefore allocate/commit a later ID while an earlier ID remains pending; a scanner advancing past that ID could miss a subsequently visible lower ID.

The target's `Minz_HookType` enum does **not** define `FeedsAfterActualize` or another post-commit hook. `EntryBeforeInsert` / `EntryBeforeAdd` are pre-commit. `actualize_script.php` reinitializes extensions per user (`app/actualize_script.php`), then invokes the per-user actualize path; `cli/actualize-user.php` explicitly calls `FreshrssUserMaintenance` and commits entries. The `FreshrssUserMaintenance` hook also runs before refresh work in `feedController.php`, so it is not evidence that new entries have already committed.

For Milestone 1, discovery must be a durable pending-ID ledger reconciled from committed entries by the separately scheduled worker. No refresh hook can safely populate that ledger after commit on this target; the implementation must not register the nonexistent `FeedsAfterActualize` hook. Do not advance the durable cursor beyond unresolved discovery work. The final implementation registers no refresh hook. Enabling snapshots currently committed IDs as already handled; repeated worker scans discover any unseen committed IDs, including late commits below the enable-time maximum. Explicit backfill is later work. This trades a growing per-user ID ledger and repeated scans for safe discovery on the official release.

## Label APIs and maintenance findings

FreshRSS 1.30.4 `p/api/greader.php::tagList()` emits categories and user labels using `user/-/label/<name>` but marks them `type: folder` and `type: tag`, respectively. `streamContentsFilters()` resolves a category name first and only looks up a tag if no category matches (`p/api/greader.php`, around lines 625ג€“645). Topic labels therefore use the configurable `Topic: ` prefix and reject category-name collisions. FreshRSS tag operations are in `app/Models/TagDAO.php`: `searchByName()`, `addTag()`, `tagEntry()`, and `tagEntry(..., checked: false)` for removal; preserve ownership per entry/tag pair so manual associations are never removed.

`config-user.default.php` sets `keep_labels` to `true`; `EntryDAO::cleanOldEntries()` (`app/Models/EntryDAO.php`, around line 815) excludes tagged entries when that option is enabled. M2 retention removes expired extension-owned label associations at the user's `keep_period` by default, allowing normal purging to resume while leaving manual associations alone.

## Consequences

The separate worker avoids blocking feed refresh and reader sync on provider availability. Durable reconciliation costs a scan and requires careful crash-safe state updates. The companion extension remains compatible with the official 1.30.4 extension API without depending on an edge-only hook. No claim of FeedMe client compatibility follows from the API shape; issue #275 remains a phone-test concern (see `feedme-manual-test.md`).

## Milestone 2 additions

Keep the per-user worker and durable committed-entry discovery model. M2 adds a keyword-first Hybrid path, cache reuse keyed by effective classifier inputs, persisted retry scheduling, and reclassification when committed classifier inputs change. These remain worker operations; refresh never waits on provider availability. Retry eligibility and backoff are durable per entry, allowing later eligible entries to proceed while an unavailable provider is retried. The default attempt cap is five.

Retain the pair-level ownership invariant: only `(entry_id, label_id)` associations recorded by Article Topics may be removed during reclassification or retention. Existing pairs remain manual even when the label name is also a configured topic.

Testing uses a Python standard-library mock with a fixed mapping for the twelve prompt fixtures. Its `/__test__/responses`, `/__test__/state`, `/__test__/reset`, and `/__test__/fixtures` endpoints exist only to drive local tests; they are not production controls and the mock must remain loopback-bound or isolated in the test container. `tests/integration/run.ps1` restricts execution to the ignored `.upstream/FreshRSS` 1.30.4 checkout. Worker mode changes that disposable installation and is not a production deployment method.

The fixture set does not constitute the requested 50-real-article evaluation. Since those articles have not been supplied, precision and recall remain unmeasured. Docker is unavailable in the current environment; the local runner uses portable PHP with the existing disposable SQLite install. Historical M2 integration and API results are recorded in `milestone-2-report.md`; they are not rerun by this documentation work.

## Release scope decision

The architecture decision remains the standalone extension and separate durable worker. This documentation records the target FreshRSS version as 1.30.4, not as an Article Topics release number. Milestone 3 form/service code for backfill and preview is now present in the shared tree, but the backfill scope values disagree between UI and service and the CLI does not run queued jobs. Diagnostics are incomplete and the admin actions have not been validated end to end. Milestone 4 CI/PHPStan, completed release security review, and versioned archive are not evidenced as complete. We therefore do not describe the current tree as a finished release or claim a real-feed quality measurement. The read-only security snapshot and its implementation risks are in `security-review.md`; scope is summarized in `release-notes.md`.

FeedMe compatibility remains unverified on a phone. Google Reader API verification is evidence about FreshRSS API behavior only; it does not establish rendering or sync behavior in FeedMe. No workaround is claimed without client-side evidence.

## Final integration resolution

Backfill scope mapping and queued execution are integrated using cli/backfill.php --next. The worker consumes saved article/time budgets. Ownership application uses public applyLabels rather than reflection. Native admin browser checks and CSRF rejection passed after moving JS/CSS to FreshRSS static asset hooks. The UI preserves prefix whitespace and exclusion rules. PHPStan analyzes production PHP at level 5, plus the real FreshRSS API contract at level 10; upstream first-party and third-party extension configs use 10 and 0 respectively. The standalone third-party level 5 choice avoids hiding source errors or claiming full level 10 coverage. Luna 6 priority review approved after two rounds. Historical audit findings above are superseded where recorded in release-notes.md and review-ledger.md. Docker and other database integration remain CI/unverified items, and Android and real-feed evaluation are not claimed.
